# 开发与实验负责人材料提供清单

> 用途：作品报告、软件工程交付材料和参赛 PPT
> 建议交付时间：2026-08-01
> 交付格式：遵循 [`experiment-handoff-template.md`](experiment-handoff-template.md)

请从实际运行服务器和实验结果中导出以下材料。没有完成或没有测量的项目请明确标记“未测量/暂无”，不要使用赛题目标值代替实测值，也不要只提供截图而缺少可计算的数据文件。

## 1. P0：必须提供的实验基础信息

### 1.1 系统与实验环境

请同时填写到 `manifest.yaml` 和 `experiment-overview.md`；前者用于机器核对，后者用于人工阅读：

- 当前实验对应的Git commit；
- 实验执行日期和负责人；
- 边缘工作节点数量；
- 各节点CPU、内存、GPU、操作系统和体系结构；
- Kubernetes、Redis、MySQL版本；
- MiniLM ONNX模型版本、文件大小和分类阈值；
- 边缘小语言模型名称、参数规模、量化方式和运行位置；
- 云端大模型名称和API类型，不提供API Key；
- 正常网络下的RTT、带宽和丢包率；
- 每组实验的重复次数和随机种子。

### 1.2 数据集与任务规模

请提供以下统计：

| 数据项 | 需要的内容 |
| --- | --- |
| 数据集 | BGL、Apache、Linux、ZooKeeper或实际使用的数据集 |
| 样本规模 | 原始日志数、事件数、模板数 |
| 类别分布 | 正常、异常及各异常类别数量 |
| 数据划分 | 训练集、验证集、测试集数量和划分方式 |
| 场景映射 | 哪些数据用于工业设备监测，哪些用于分布式基础设施监测 |
| 关联任务 | 多节点一致性实验如何将事件组成关联任务 |

## 2. P0：必须提供的实验结果

所有汇总结果写入 `results.csv`，必要的逐轮结果放入 `raw/`。

### 2.1 边缘模型效果与资源占用

至少提供实际使用模型的数据：

- Accuracy、Macro-F1、高风险Recall；
- 边缘推理P50/P95时延；
- 模型文件大小；
- 峰值内存；
- 吞吐量；
- 如果测量了生成式模型，提供TTFT；
- 如果已与云端模型对比，提供边缘模型能力保持率及计算方法。

如已有MiniLM、DistilBERT和边缘小语言模型对照结果，请分别提供；没有运行的模型不要补造。

### 2.2 云边协同主实验

请至少提供RAISE实际结果；如已运行基线，同时提供：

- All-Local；
- All-Cloud；
- Confidence-Threshold；
- Static-Cascade；
- RAISE。

每种方法需要的指标：

- Macro-F1和高风险Recall；
- 端到端P50/P95/P99时延；
- 上云事件比例；
- 上传字节数或通信量；
- 平均Token/事件；
- 云端调用次数及已有的费用统计；
- 总任务成功率。

### 2.3 弱网和恢复实验

请按实际已运行的网络条件提供：

- 正常网络；
- 高时延；
- 网络波动；
- 完全断网；
- 网络恢复。

每种条件需要：

- RTT、丢包率、带宽和持续时间；
- 本地有效决策率；
- 总任务成功率；
- `DEFER`事件数；
- Outbox最大积压量；
- 补传成功率；
- 网络恢复后Outbox清空时间；
- 故障或异常说明。

### 2.4 多节点一致性实验

如该实验已经完成，请提供：

- 场景名称和关联任务定义；
- 关联任务总数；
- 初始决策冲突数；
- 决策冲突率；
- 成功统一或纠正的冲突数；
- 冲突解决成功率；
- 冲突主要来源：模型判断、模板版本、观测窗口或其他原因。

如果当前没有专门的一致性实验，请明确说明，不用从普通事件统计中推断。

## 3. P1：已有则提供的补充实验

### 3.1 RAISE消融实验

如果已经运行，请提供：

- RAISE-full；
- 无不确定性校准；
- 无在线反馈；
- 固定阈值；
- FIFO Outbox；
- 无模板新颖度/历史分歧特征。

主要指标为Macro-F1、高风险漏报率、上云比例、P95时延和弱网成功率。

### 3.2 长时间运行与故障记录

如已有连续运行、服务重启、Redis/MySQL暂时不可用或云端API失败记录，请提供运行时长、处理事件数、失败数、恢复结果和相关日志。

## 4. P0：必须提供的运行截图

截图尽量使用1920×1080或更高分辨率，浏览器缩放保持一致。截图中不得出现API Key、真实Tailscale地址、个人通知、聊天窗口或无关桌面内容。

| 编号 | 截图内容 | 画面必须包含 | 用途 |
| --- | --- | --- | --- |
| S-01 | 系统总览/实时大盘 | 系统状态、事件流、核心指标 | 报告系统实现、PPT总体展示 |
| S-02 | 多设备持续接入 | 设备列表或多个设备来源、采集状态 | 证明分布式感知 |
| S-03 | 边缘推理结果 | 类别、置信度、严重度、推理路径 | 说明边缘分层推理 |
| S-04 | RAISE路由解释 | `LOCAL/CLOUD/DEFER`、分数、阈值和原因 | 说明动态任务调度 |
| S-05 | 云端诊断证据 | MySQL `cloud_feedback` 查询、Redis `cloud.resp` 或服务日志中的根因、解释、建议与置信度；不得用现有 Web 页面替代 | 说明网关产生并持久化了结构化诊断 |
| S-06 | 弱网期间状态 | 云端不可达或网络异常、`DEFER` 和 Outbox 变化 | 观察弱网延期机制，不预设业务保持结论 |
| S-07 | 链路恢复观察 | Outbox 重试、积压变化和云端请求处理结果 | 验证实际恢复效果，不预设清空或全部成功 |
| S-08 | 规则与模板管理 | 规则/模板列表、发布或启用状态 | 说明系统可配置性 |
| S-09 | 模型与Provider管理 | 边缘模型和云端Provider状态，隐藏敏感字段 | 说明模型可替换与热更新 |
| S-10 | Kubernetes运行状态 | 核心Pod、工作节点和服务均为健康状态 | 证明实际部署运行 |

如果两类应用场景在大盘中有明显不同的数据或设备命名，再分别提供一张场景截图；如果没有明显视觉差异，则由实验数据和架构图说明，不重复截图。
