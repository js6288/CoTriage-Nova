# CoTriage 统一术语表

> 版本：V1.0
> 冻结日期：2026-07-29

作品报告、软件工程交付材料和参赛 PPT 统一使用下列术语与大小写。

## 1. 项目与方法

| 标准写法 | 含义与使用规则 |
| --- | --- |
| CoTriage | 项目英文名，大小写固定，不写作 Cotriage 或 Co-Triage |
| 面向工业多设备日志的云边协同智能故障感知与决策系统 | 作品中文名称 |
| RAISE | 云边自适应路由方法简称 |
| Risk-Aware, Uncertainty-Calibrated, Intent-Constrained, Self-Adaptive Edge-Cloud Routing | RAISE 英文全称；首次出现时给出全称，后续使用简称 |
| 云边协同 | 边缘侧实时初判与云端深度诊断之间的动态协作机制 |
| 边缘集群 | 部署在工厂、车间、园区或站点近端的 Kubernetes 集群，不等同于单台终端设备 |
| 云端大模型 | 通过 OpenAI-compatible API 接入、用于根因分析和处置建议生成的模型 |
| 边缘小语言模型 | 部署在边缘侧或边缘可达环境、用于异常细分类的轻量语言模型 |

## 2. 组件名称

| 标准写法 | 职责 |
| --- | --- |
| `log-collector` | 采集工作节点日志并写入原始事件流 |
| `edge-infer` | 执行规则、模板、MiniLM ONNX、边缘小语言模型和降级推理 |
| `router-controller` | 执行 RAISE 路由、运行时状态管理、Outbox 到期重试和反馈更新 |
| `cloud-gateway` | 聚合上下文、对主日志和关联原始日志脱敏，并调用云端模型完成深度诊断 |
| `server` | 提供控制面、查询接口和 REST/SSE API，不表述为云端推理执行者 |
| `web` 或 Web 管理端 | 提供实时大盘、设备和配置管理页面 |
| Redis Streams | 系统事件流与消费者组基础设施 |
| MySQL | 配置、路由状态、Outbox 和云端反馈的持久化存储 |

## 3. 事件与动作

| 标准写法 | 定义 |
| --- | --- |
| Event / 事件 | 一次需要系统进行分诊决策的最小处理单元；当前实现以单条日志事件为主 |
| `event_id` | 串联采集、推理、路由和云端反馈的全链路唯一标识 |
| `LOCAL` | 采用边缘结果，在边缘侧完成当前决策 |
| `CLOUD` | 当前条件允许，立即发送云端进行深度诊断 |
| `DEFER` | 事件值得上云但当前发送条件不满足，保留边缘判断并进入 Outbox |
| Outbox | 保存延期云端请求并周期处理到期记录的持久化机制；当前 replayer 不使用云健康门控 |
| DLQ | Dead Letter Queue，超过重试上限或不可恢复事件的死信队列 |
| 云端反馈 | 云端诊断产生的纠错、有效信息增益和收益信号 |
| Reward | 云端诊断相对边缘结果的增益评分；公式或字段名使用英文，正文可写“收益” |

## 4. 模型与指标

| 标准写法 | 使用规则 |
| --- | --- |
| MiniLM ONNX 轻量分类器 | 负责 `NON_ALERT/ALERT` 边缘二分类，不称为完整根因诊断模型 |
| OpenAI-compatible | 形容兼容 OpenAI API 协议的模型接口，英文连字符写法固定 |
| Macro-F1 | 宏平均 F1 值 |
| 高风险 Recall | 高风险事件召回率；报告中需同时给出高风险定义 |
| P50/P95/P99 | 时延分位数，首次出现时说明统计对象和单位 |
| E2E 时延 | 端到端时延；必须明确起点、终点及是否包含云端诊断 |
| TTFT | Time to First Token，首次出现时给出英文全称和测量口径 |
| 基本业务功能保持率 | 弱网期间成功产生本地有效决策的事件数除以弱网期间事件总数 |
| 决策冲突率 | 关联任务中产生不一致决策的次数除以关联任务总数 |
| 冲突解决成功率 | 最终被统一或正确纠正的冲突数除以冲突总数 |

## 5. 禁止或避免的写法

- 不使用拼写错误 `DEFFER`，统一为 `DEFER`。
- 不使用含义模糊的“router”“gateway”代替正式组件名称。
- 不把规则、模板或 MiniLM 的判断表述为云端大模型诊断。
- 不把赛题目标值、预期值或配置阈值表述为实测结果。
- 不笼统写“毫秒级”“低资源”或“高准确率”，必须同时给出测量口径和数据。
- 不在同一文档中混用“端侧节点”“边缘节点”“工作节点”；涉及 Kubernetes 时统一写“工作节点”，涉及计算层级时使用“边缘侧”。
