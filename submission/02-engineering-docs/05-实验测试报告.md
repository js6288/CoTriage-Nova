## 2. 测试对象与范围

### 2.1 核心链路

测试范围覆盖：

1. `log-collector`：新增日志行读取、事件生成、设备标识和 raw Stream 发布；
2. `edge-infer`：规范化、规则、模板、MiniLM ONNX、边缘小语言模型、降级、Pending、幂等、DLQ 和远程配置；
3. `router-controller`：RAISE 三动作、运行状态、决策落库、请求发布、Outbox、反馈和快照；
4. `cloud-gateway`：请求解码、上下文聚合、脱敏、Provider 调用、结构化输出、反馈、响应和 DLQ；
5. `server`：设备、事件、大盘、Router、规则、模板、分类器及 Provider REST/SSE API；
6. `web`：首页、分诊大盘、设备、规则、模板、模型和可选数字人页面；
7. 数据链路：Redis Streams、MySQL 以及 Kubernetes 运行状态。

### 2.2 不在本轮执行的内容

- 不在文档编写机上启动 `start-cotriage.sh`；
- 不清空 Redis，不重启集群采集器；
- 不连接或运维队友服务器；
- 不训练模型、不运行全量数据预处理、不执行 GPU/长时间/弱网正式实验；
- 不根据历史截图反推数字；
- 不把数字人功能纳入核心云边协同指标。

正式实验应在队友控制的目标环境执行。本地设备为 RTX 3060 6 GB、R7 5800H、32 GB 内存，不用于代替正式多节点或大模型实验环境。

### 5.2 事件契约与异常用例

| 用例 | 场景 | 预期检查 |
| --- | --- | --- |
| CT-01 | raw 事件缺少 `event_id` 或 `log.raw` | `edge-infer` 不发布伪造结果，按尝试策略处理并最终进入 DLQ |

| CT-07 | `edge-config` ETag 未变化 | 返回 304，`edge-infer` 保持当前配置 |
| CT-08 | 新远程配置非法 | 拒绝整批应用并保留上一份可用运行配置 |

## 8. 对比方法与实验控制

主实验计划比较：

| 方法 | 定义 |
| --- | --- |
| All-Local | 所有事件采用边缘结果，不调用云端 |
| All-Cloud | 所有符合输入条件的事件调用云端；网络失败的处理规则需单独说明 |
| Confidence-Threshold | 仅依据固定置信度门槛决定是否上云 |
| Static-Cascade | 固定规则或固定级联顺序，不使用在线系统态和反馈调整 |
| Queue-Aware | 只依据队列和预算调整动态阈值，不使用完整 RAISE 的风险、不确定性与在线反馈特征 |
| RAISE | 使用当前完整的风险、不确定性、收益、成本、动态门槛和策略约束 |

为保证可比性，同一组实验应固定数据版本、事件顺序或随机化规则、模型版本、Prompt、最大 Token、超时、并发、运行时长和指标采集方法。每种方法使用相同重复次数；报告均值时同时给出离散程度或置信区间，并保留逐次运行结果。

RAISE 默认权重、阈值和预算属于待冻结配置，不得在看到测试集结果后无记录调参。配置证据：`【待证据：EVID-EXP-MANIFEST-01】`。

## 9. 指标定义

### 9.1 效果指标

- **Accuracy：** 正确预测数除以样本总数。
- **Macro-F1：** 对每个类别分别计算 F1 后做等权平均；类别集合和 `UNKNOWN` 的处理必须说明。
- **高风险 Recall：** 被正确识别的高风险事件数除以真实高风险事件总数；“高风险”标签集合必须在实验前冻结。
- **边云分歧率：** 云端预测与边缘预测不同的可比较事件数除以有完整双侧结果的事件数；它不自动表示云端一定正确。

Reward 必须分两阶段报告。Cloud Gateway 先计算并截断连续值

\[
r_{gateway}=\operatorname{clip}_{[-1,1]}(0.35D+0.30A+0.20H+0.15\Delta c-0.10L-0.05T),
\]

其中 \(D\) 为云端类别不为 `UNKNOWN` 且与边缘类别不一致、\(A\) 为根因与建议均非空、\(H\) 为严重度不低于 75 且云端置信度不低于 0.65，\(\Delta c\) 为非负置信度增量，\(L\) 与 \(T\) 为截断到 1 的归一化时延与 Token 成本。Router 随后按首个匹配条件将其重新分类为：纠正边缘 `1.0`、提供可执行信息 `0.7`、确认高风险 `0.3`、无新增信号 `0.0`。`ApplyFeedback` 和最终数据库列实际使用 Router 离散值，`FinalizeFeedbackReward` 会覆盖 Gateway 最初写入的连续值。实验包必须保存处理前后记录，不能把两套 Reward 合并统计；该差异是待统一的实现语义，不是效果提升证据。

### 9.2 时延与吞吐

- **边缘推理时延：** 从 `edge-infer` 开始处理事件到 inferred 结果完成的时间，单位 ms，报告 P50/P95；
- **路由时延：** RAISE 处理及输出的耗时，单位 ms，报告 P50/P95；
- **E2E 时延：** 必须分别定义本地路径和云端路径的起止点，并说明是否包含排队、网络、TTFT 和完整生成；报告 P50/P95/P99；
- **TTFT：** Time to First Token，从云端请求开始到收到首个 Token 的时间，单位 ms；如果 Provider 非流式返回且无法测量则保持为空；
- **吞吐量：** 稳态测量窗口内成功完成指定阶段的事件数除以窗口秒数，单位 events/s。

所有时延使用同一时钟或说明跨节点时钟同步方法。超时与失败样本是否纳入分位数必须预先定义。

### 9.3 资源与成本

- 模型文件大小和峰值内存统一使用 MB，并说明 MB 的换算方式；
- CPU、GPU 和内存采样工具、采样间隔、容器/进程边界必须记录；
- 上云比例 = `CLOUD` 事件数 / 路由事件总数；`DEFER` 后最终补传是否计入需给出两种口径或明确唯一口径；
- 上传量使用字节，说明只统计 HTTP Body、应用层还是包含协议开销；
- Token/事件、云端调用次数和费用必须说明 Provider 计数来源、币种与计价时间；
- “能力保持率”只有在边缘与参照模型使用同一任务、同一测试集、同一指标时才计算，公式为边缘指标除以参照指标。

### 9.4 弱网与一致性

当前 replayer 不检查网络恢复、云健康、预算或速率条件，只按记录到期、锁状态和 Redis 发布结果工作。正式实验应把网络条件作为独立变量同步记录，分别测量“请求已发布”和“云端已处理”，不能把恢复时刻当作代码中的重放触发器。

- **基本业务功能保持率：** 弱网期间成功产生本地有效决策的事件数 / 弱网期间事件总数；“有效”需按标签或业务规则定义；
- **总任务成功率：** 在规定截止时间内得到满足任务验收条件结果的事件数 / 事件总数；
- **Outbox 请求发布成功率：** 观测窗口内到达 `SENT` 的目标事件数 / 应重放目标事件总数；`SENT` 只表示 Redis `XADD` 成功；
- **云端完成率：** 观测窗口内获得可核验 MySQL `cloud_feedback` 的目标事件数 / 已发布目标事件总数；不得用 `SENT` 或 `done_at` 代替；
- **Outbox 活动队列清空时间：** 从预先声明的观测起点到目标集合不再处于 `PENDING/RETRY/SENDING` 的时间，单位 s；同时单列 `DLQ`，避免把失败退出误算为成功；
- **决策冲突率：** 关联任务中出现不一致决策的任务数 / 关联任务总数；
- **冲突解决成功率：** 最终被统一或正确纠正的冲突任务数 / 冲突任务总数。

## 13. 验收判定规则

- 单元、契约和集成用例必须分别报告，不能用一个“整体通过”掩盖未执行项；
- 正式指标至少提供每次运行结果与汇总方法，不能只给截图；
- 对比方法使用相同数据与资源边界，任何例外必须解释；
- 失败、缺失和人工干预如实记录；
- 配置阈值、赛题目标和历史样例不得写入“实测结果”列；
- 安全阻断项不因算法指标较好而豁免；
- 结论使用“在给定数据、环境和测量口径下”限定适用范围；
- 在证据到达前，本报告不得出现“显著提升”“达到要求”“稳定运行”等无支撑表述。
