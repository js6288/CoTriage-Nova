## 事实源优先级

文档冲突时按以下顺序取事实，并保留来源说明：

1. 当前代码、配置、依赖清单和实际注册的接口；
2. 根目录及组件 README 中与当前实现一致的运行说明；
3. `design_doc/` 中仍与代码一致的设计解释；
4. `progress_doc/` 中的历史过程材料，仅用于核对演进，不作为当前验收结论；
5. `sop/` 中经环境复核和脱敏后的操作经验。

## 证据约定

- 证据编号只复用 `submission/03-evidence/evidence-index.yaml` 中登记的编号；
- `【证据：EVID-...】` 表示已有本地静态材料可追溯，仍不等于实机性能结论；
- `【待证据：EVID-...】` 表示需要外部运行记录、截图或实验数据，收到前保持占位；
- 未测量字段保持为空或明确写“未测量”，不以 `0`、目标值、配置阈值或历史样例代替；
- “显著提升”“达到要求”“稳定运行”等结论必须同时具备原始数据、统计口径和对应证据编号。

## 当前能力边界

- `LOCAL` 表示保留并发布边缘路由结果，当前核心代码没有直接调用现场告警器或执行器；
- `CLOUD` 表示向云端请求 Stream 发布请求，不等于云端诊断已经完成；
- `DEFER` 表示将请求持久化到 Outbox。replayer 按到期时间周期尝试向 Redis 发布，没有网络恢复或云健康门控；
- Outbox 当前活动流为 `PENDING/RETRY -> SENDING -> SENT`，失败转 `RETRY` 或 `DLQ`。`SENT` 只证明 Redis `XADD` 成功，不证明云端已处理；
- `cloud-gateway` 会将反馈写入 MySQL 并发布 `cloud.resp`，但 Server 目前只统计该 Stream 长度，Router 的反馈处理器读取 MySQL，Web 尚不展示云端根因、建议和置信度。
- feedback processor 会更新模板统计和 GainModel 快照，但 `BuildStats` 当前丢弃 learned gain，实际决策只通过历史分歧与 UCB 间接受反馈影响，学习闭环尚未完全贯通。

## 发布前检查

所有公开版本必须扫描真实 IP、私有组网节点、账号、API Key、Token、密码、内部路径、原始日志和个人信息。`sop/`、终端输出和截图只能在脱敏并确认与目标环境一致后进入交付包。
