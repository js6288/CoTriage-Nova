## 1. 系统用途

CoTriage 用于持续接入多设备或多节点日志，在边缘侧完成快速初判，再由 RAISE 记录并发布 `LOCAL`、`CLOUD` 或 `DEFER` 路由结果。`LOCAL` 保留边缘判断供人员或外部现场系统消费，`CLOUD` 将请求发布到云端请求流，`DEFER` 将请求持久化到 Outbox 后由 replayer 按到期条件周期尝试发布；当前代码没有直接执行现场处置，也没有以“网络恢复”事件触发重放。用户主要通过 Web 管理端观察事件流、检查设备接入状态、维护规则和模板、配置边缘与云端模型，并查看三种路由动作及 Outbox 状态。

系统输出用于辅助故障感知、根因分析与处置决策，不应在缺少现场复核、安全联锁或组织授权的情况下直接替代人工执行高风险操作。

## 2. 用户职责与访问边界

当前系统代码未实现完整的应用内角色权限控制。下列角色是操作职责划分，不代表软件已经强制执行这些权限：

| 角色 | 建议职责 | 不应执行的操作 |
| --- | --- | --- |
| 观察者/评审者 | 查看实时大盘、设备状态、路由解释和演示结果 | 修改规则、模板或模型配置；查看任何真实凭据 |
| 运维人员 | 监视事件、识别异常、核对 Outbox 和服务状态 | 未经审批清空 Redis、修改数据库或替换生效模型 |
| 规则与模型管理员 | 创建、编辑、发布规则/模板，维护模型 Provider | 在截图、聊天或文档中传播 Endpoint 内网地址和 API Key |
| 部署负责人 | 启停组件、注入配置、排障、备份与恢复 | 在未确认目标环境前执行根启动脚本或破坏性清理命令 |

建议通过网络隔离、反向代理鉴权和最小权限账号限制管理端访问。所有敏感配置由部署负责人注入，不在用户手册中记录真实值。

## 4. 实时日志分诊大盘

### 4.1 顶部指标

大盘顶部显示当前事件处理快照。常用指标含义如下：

| 指标 | 含义 | 观察建议 |
| --- | --- | --- |
| 近一分钟接入 | 最近一分钟进入原始事件流的事件数 | 与设备产生速率对照，判断采集是否中断 |
| 近一分钟推理 | 最近一分钟完成边缘推理的事件数 | 长期低于接入速率时检查推理积压 |
| 待确认消息 | 已由 Consumer Group 读取但尚未成功 ACK 的消息数 | 持续增长时检查处理耗时、模型超时或 Redis 连接 |
| P95 推理时延 | 边缘推理时延的第 95 百分位 | 必须结合统计窗口和单位解释，不可单独当作端到端时延 |
| 异常日志比例 | 当前统计窗口中异常事件占比 | 用于发现异常抬升，不等同故障准确率 |
| 降级比例 | 走 `FALLBACK` 路径的事件占比 | 抬升时检查模型配置、模型服务或输入质量 |
| 累计完成推理 | 当前数据窗口可见的推理完成量 | 仅表示处理量，不表示全部结果正确 |
| 死信消息 | 进入 DLQ 的消息数量 | 大于零时检查坏消息、格式错误或持续失败 |
| RAISE 路由总量 | `router-controller` 已落库的路由决策量 | 显示 Degraded 时检查 Router、MySQL 表和连接 |
| Cloud 路由比例 | 被选择为 `CLOUD` 的路由比例 | 结合网络、预算和任务风险解释 |
| Defer 队列 | `PENDING` 与 `RETRY` 中等待到期重放的项目 | 持续增长时核对到期时间、锁、重试次数与 Redis 发布路径；当前 replayer 不以网络恢复或云健康为门控 |
| P95 路由时延 | 路由决策时延第 95 百分位 | 不包含完整云端诊断时延 |

指标实机截图与采集口径：`【待证据：EVID-UI-01】`。

### 4.2 推理与异常态势

大盘提供处理趋势、日志分类分布、推理路径分布和异常态势分析。推理路径按以下含义解释：

- `RULE`：命中确定性规则；
- `CACHE`：命中配置模板或 Redis 模板缓存；
- `MODEL`：由 MiniLM ONNX 轻量分类器完成 `NON_ALERT/ALERT` 初筛；
- `EDGE_LLM`：分类器判定异常后，由边缘小语言模型进一步细分；
- `FALLBACK`：上游路径未配置、不可用或无法完成判断，输出保守降级结果。

异常聚合卡片可以显示模板、分类、影响设备、主要推理路径和处理优先级。用户可点击“沉淀为模板”，系统按 `template_id` 幂等地创建模板草稿；草稿仍需审核并发布后才进入生效配置。

### 4.3 RAISE 状态与动作

大盘的 RAISE 面板显示 `LOCAL/CLOUD/DEFER` 分布，以及“上云压力”“路由门槛”“最近去向”“运行版本”等信息：

- `LOCAL`：保留并发布边缘路由结果，本次事件不进入云端深度诊断；当前核心代码不据此直接触发现场告警器或执行器；
- `CLOUD`：当前网络、预算和策略允许，事件被发布到云端请求流；这只表示请求已入流，不表示云端诊断已经完成；
- `DEFER`：事件值得上云但初始决策时不可发送，先持久化到 Outbox；replayer 后续按记录是否到期及锁状态周期尝试 Redis 发布，不重新检查网络、云健康、预算或速率条件。

“上云压力”是路由评分的展示名称，“路由门槛”会受队列、预算、网络及审计压力影响。不能仅凭某个分数断言事件正确或错误；应同时查看动作、原因、边缘分类、严重度、置信度、推理路径和云端健康状态。当前 Web 展示边缘事件与路由信息，不展示云端根因、建议或云端置信度；这些字段不能从现有大盘截图中声称已经可见。

RAISE 动作与解释截图：`【待证据：EVID-UI-01】`。

### 4.4 实时事件流

实时事件表通过 SSE 接收新增事件。用户可以：

1. 查看事件 ID、时间、设备、分类、严重度、置信度、推理路径和日志摘要；
2. 展开或结合路由记录查看对应的动作、分数、门槛和原因；
3. 点击“暂停刷新”冻结当前视图；
4. 暂停期间新事件会暂存到页面内，点击“载入新事件”后合并显示；
5. 恢复后如页面长期无更新，检查浏览器连接、Server 和 SSE 接口。

暂停刷新只影响前端展示，不会暂停后端采集、推理或路由。

## 5. 设备管理

设备管理页展示 Kubernetes 工作节点及其日志采集状态。当前支持按车间、设备和状态筛选，并可进入设备详情。

建议操作流程：

1. 进入“设备管理”；
2. 按需输入车间或设备名称，或选择 `Ready`、`NotReady`、`Unknown`；
3. 点击“查询”；
4. 检查节点名、设备标识、节点状态、采集器状态、最近事件时间和接入速率；
5. 点击设备记录进入详情页，核对基础信息、接入信息和运行状态。

设备由 Kubernetes 工作节点及其 `cotriage.io/equipment`、`cotriage.io/site` 标签映射。CoTriage 当前提供查看能力，不负责在界面内加入或移除工作节点。

多设备持续接入截图：`【待证据：EVID-UI-01】`。

## 6. 规则管理

规则用于快速处理确定性强、可解释的日志模式。当前页面支持列表、新增、编辑、删除，以及“发布并启用当前规则”。

### 6.1 新增或编辑规则

1. 进入“规则管理”，点击“新增规则”或目标规则的“编辑”；
2. 填写名称、说明、匹配类型、目标字段、匹配内容或关键词；
3. 设置输出分类、严重度、置信度、证据、建议编码、建议、优先级和启用状态；
4. 点击保存；
5. 保存后复核列表中的状态和内容。

保存只维护规则条目，不等于边缘实例已经使用该规则。用户需要点击“发布并启用当前规则”，页面会将当前启用条目组成新的规则集并激活。`edge-infer` 通过 Server 的配置接口轮询更新；最终是否生效必须由配置版本和实际命中记录确认。

注意：规则优先级、输出分类和处置建议会直接影响边缘结果。发布前应由另一名技术成员复核，避免过宽匹配导致误判。

规则发布及命中证据：`【待证据：EVID-UI-01】`；静态接口能力对应 `【证据：EVID-ENG-01】`。

## 7. 模板知识库

模板知识库用于复用已经确认的日志模式及其分类、严重度、置信度、证据和建议。当前支持列表、新增、编辑、删除，以及“发布并启用当前模板”。

### 7.1 人工维护模板

1. 进入“模板知识库”，点击“新增模板”或目标模板的“编辑”；
2. 填写日志模板、原始日志示例、来源、输出分类、严重度、置信度、证据、建议编码和处理建议；
3. 保存后检查条目状态；
4. 审核所有拟启用模板，再点击“发布并启用当前模板”。

原始日志示例必须脱敏，不得含密码、Token、API Key、真实私有地址、邮箱或个人信息。置信度是配置值，不应在报告中写成模型实测准确率。

### 7.2 从异常聚合沉淀

在实时大盘的异常聚合或优先处理条目上点击“沉淀为模板”，系统会生成草稿。若相同 `template_id` 已存在，后端返回已有模板而不是重复插入。用户仍需进入模板知识库核对样例、分类和建议，再发布模板集。

模板沉淀、发布和生效证据：`【待证据：EVID-UI-01】`；静态接口能力对应 `【证据：EVID-ENG-01】`。

## 8. 模型管理

模型管理页分为三个标签页。

### 8.1 轻量分类模型

用于管理 MiniLM ONNX 等 HTTP 分类器配置。用户可维护名称、Endpoint、模型版本、超时、告警阈值和状态，并执行保存、启用或删除。

MiniLM 当前只承担 `NON_ALERT/ALERT` 二分类，不是完整根因诊断模型。启用前应确认模型服务健康、版本匹配、阈值来源清楚。启用后需通过 `edge-config` 配置版本和 `MODEL` 路径事件验证生效。

### 8.2 边缘小语言模型

用于管理 OpenAI-compatible 或其他受支持的边缘模型 Provider。配置包含名称、Provider 类型、Endpoint、模型名、超时、生成参数、响应路径和健康检查路径。边缘小语言模型只在上游分类器判定为异常且配置可用时参与细粒度分类。

Endpoint 可能暴露内部网络拓扑，公开截图时必须遮蔽或使用演示地址。

### 8.3 云端大模型

用于管理云端 Provider 的名称、类型、Endpoint、模型、API Key 变量名、API Key 及调用参数。操作顺序为创建或编辑配置、保存、复核、启用。

安全要求：

- 真实 API Key 只由授权管理员录入，不粘贴到文档、聊天或截图；
- 当前实现属于 Demo 级凭据管理，控制面访问必须限制在可信边界；
- 录入前确认浏览器录屏、共享屏幕和开发者工具没有暴露敏感字段；
- 公开演示建议使用专用、限额、可撤销的凭据；
- 启用后通过 cloud-gateway 日志和结构化响应确认热更新，不通过显示明文凭据来“验证”。

三类模型配置和生效证据：`【待证据：EVID-UI-01】`；静态接口能力对应 `【证据：EVID-ENG-01】`。

## 9. 弱网与故障状态处理

当事件具有上云价值但初始决策时网络、云端健康、速率或预算不允许发送时，RAISE 输出 `DEFER`，事件进入 Outbox。之后的 replayer 只按数据库中的到期与锁条件周期工作，不以网络恢复、云健康、预算或速率为门控。用户应：

1. 在大盘查看 Defer 队列与 Outbox 列表；
2. 核对推迟原因、优先级、尝试次数和最近错误；
3. 同时检查边缘判断和路由记录是否仍有有效输出；当前核心代码不直接执行现场告警或处置；
4. 观察活动状态是否按 `PENDING/RETRY -> SENDING -> SENT` 变化，或失败后回到 `RETRY`/进入 `DLQ`；`SENT` 只表示 Redis `XADD` 成功，不代表云端处理完成；
5. 若持续积压，交由部署负责人检查 `next_retry_at`、锁是否过期、尝试次数、replayer 状态和 Redis 请求流发布路径，再单独检查 cloud-gateway 的后续消费；
6. 不通过直接改库或清空 Redis 的方式掩盖积压。

弱网前后对照证据：`【待证据：EVID-EXP-WEAKNET-01】`。

## 10. 常见问题

### 10.1 大盘显示 Router 为 Degraded

优先检查 `router-controller` 是否运行、MySQL 中路由相关表是否存在、Server 是否能连接 MySQL。列表和汇总接口具有降级保护，表未创建时可能返回空数据而不是使 Server 崩溃，因此“页面能打开”不等于 Router 主链路正常。

### 10.2 事件持续进入但推理量不增长

检查 `edge-infer` 日志、Redis Consumer Group Pending、分类器或边缘小语言模型超时，以及原始事件字段是否完整。`FALLBACK` 抬升时还需检查配置拉取和模型 Endpoint。

### 10.3 已保存规则或模板但没有命中

确认是否执行“发布并启用”，再核对 `edge-infer` 是否已拉取新配置、配置版本是否变化、规则目标字段与规范化后的文本是否匹配。保存草稿本身不会保证立即生效。

### 10.4 云端诊断没有结果

先区分“请求已发布”“反馈已持久化”“响应已发布”和“界面已展示”四个阶段。当前 Web 不展示云端根因、建议或置信度；Server 只统计 `cotriage.events.cloud.resp` 的长度，不消费其内容；Router 的 feedback processor 从 MySQL `cloud_feedback` 读取未处理反馈，也不消费该响应流。因此页面没有云端诊断字段不一定表示模型未执行。应在授权环境中核对激活 Provider、cloud-gateway 日志、云端请求消费、脱敏后的 MySQL 反馈记录和响应发布记录，不得打印 API Key。若交付目标要求页面展示云端诊断，需要另行实现响应查询或消费接口。

### 10.5 Outbox 长期不下降

云端健康、网络失败率、预算与速率限制影响初始 RAISE 决策，但当前 replayer 不以这些状态作为重放门控。应检查记录是否为到期且未锁定的 `PENDING/RETRY`、`next_retry_at`、`lock_until`、尝试次数、最近错误、replayer 是否启用，以及向 `cotriage.events.cloud.req` 执行 Redis `XADD` 的结果。达到上限进入 `DLQ` 的事件需单独分析；进入 `SENT` 也只证明请求发布成功，不证明 cloud-gateway 或外部模型已经完成处理。

### 10.6 数字人无法连接

数字人是独立的可选增强功能。其失败不影响日志采集、边缘推理、RAISE 路由、云端诊断或管理端核心功能。敏感的第三方 Token 不得写入公开问题记录。
